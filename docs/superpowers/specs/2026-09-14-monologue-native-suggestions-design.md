# Monologue — 원어민 표현: 교정 칩 suggestion + `💡 뭐라고 하지?` 설계

- 날짜: 2026-09-14
- 상태: 사용자 승인(설계 1/2·2/2)
- 묶은 항목: Phase 2 다음 순서의 3번(피드백 3라운드)과 6번(추천 대사)
- 선행: Whisper 최종 받아쓰기(`d96f37c`), 번역 한글 검사(`_is_korean_meaning`), 읽기 보조(`annotate`)

## 왜

두 요청은 같은 욕구다 -- **"내가 아직 못 가진 표현을 달라"**.

- 3번: 교정 칩의 `이렇게도`가 지금은 "네 문장 다듬기"다. 학습자에게 필요한 건
  "이 상황에서 원어민은 뭐라고 하는가"다. 문맥(시나리오·목표·봇 직전 말·수업 주제)은
  이미 피드백 프롬프트에 들어가 있는데, 프롬프트가 "판단에만 쓰고 답에 옮기지 말라"고 막고 있다.
- 6번: 봇이 말하면 뭐라고 대답할지 막막하다. 말하기 **전에** 받을 수 있는 도움이 없다.

같은 엔진("이 상황의 원어민 한마디")을 두 자리에서 쓴다: 말한 **뒤**(①), 말하기 **전**(②).

## ① 교정 칩 suggestion

### 바뀌는 것 (`app/prompts.py`)

- `FEEDBACK_SYSTEM`의 suggestion 정의를 바꾼다:
  **학생이 하려던 뜻은 유지하되, 이 상황(봇이 직전에 한 말, 대화 목표)에서 원어민이 실제로 할 법한 한마디.**
  correction과 같은 지적을 되풀이하지 않고, `fixed`를 그대로 인용하지 않는다. 한국어 두 문장 이내, 인용 예문만 목표 언어.
- `_feedback_context`의 머리말 "판단하는 데만 쓰고, 답변에 그대로 옮기지 마세요"를
  **"학생이 무엇을 말하려 했는지 판단하고, suggestion을 이 상황에 맞추는 데 쓰세요. 문맥 문장을 그대로 베끼지는 마세요."** 로 바꾼다.
- `FEEDBACK_EXAMPLES`의 모양(사용자 턴 `학생이 말한 문장: ...`, JSON 다섯 필드)은 **그대로**.
  `build_feedback_messages` docstring이 기록한 이유(쿼리 턴만 모양이 다르면 모델이 그 차이에 끌린다) 때문이다.
  예시 suggestion 문구만 대화체 대안으로 다듬는다 -- 예시 문장이 `fixed`를 그대로 되풀이하지 않게.

### 새 가드 (`app/api.py`)

- **`fixed` 되풀이 가드:** `ok is False`인 실제 교정에서, suggestion 속 인용 구간 중 하나가
  `normalize(fixed)`와 **같으면**(포함이 아니라 같음) suggestion을 None으로 버린다.
  같은 문장을 `교정`과 `이렇게도`에 두 번 보여주는 것은 정보가 없다.
  기존 `_drop_self_quoting_suggestion`(학습자 원문과 같은 인용을 버림)과 같은 비교 규칙을 쓴다 -- 인용 구간 정규식과 `normalize`를 공유한다.
- 중립 처리 경로(구두점만 다른 교정)는 지금과 같다. 그 경로의 `_drop_self_quoting_suggestion`도 유지.

### 안 바뀌는 것

`ok`·`fixed`·`tag`·`correction`의 정의, 태그 목록과 정의, 스키마, 구두점만 다른 교정의 중립 처리
(Whisper가 구두점을 붙이지만, 구두점은 여전히 학습자의 실수가 아니라 받아쓰기의 것이다), 저장 필드.

## ② `💡 뭐라고 하지?`

### 엔드포인트

`POST /api/sessions/{session_id}/suggest` -- 본문 없음. 응답:

```json
{"replies": [{"text": "...", "meaning": "..." | null, "audio_key": "..." | null}, ...]}
```

| 조건 | 응답 |
|---|---|
| 세션 없음 | 404 |
| 대본 모드 | 400 (대본 모드는 할 말이 이미 정해져 있다) |
| 끝난 세션 | 409 |
| 봇 대사가 아직 없음 | 409 |
| 검증을 통과한 줄이 0개 (재시도 후) · 모델 실패 | 503 `"지금은 추천을 만들 수 없어요"` |

서버가 문맥을 직접 모은다(클라이언트가 보내는 것을 믿지 않는다):
마지막 봇 메시지(`id`, `text`), 시나리오 `title`·`goal`(자유) 또는 `topic`(수업), `db.stable_level(language) or "beginner"`,
최근 대화 최대 6개 메시지.

### 프롬프트 (`app/prompts.py`: `SUGGEST_SYSTEM`, `suggest_schema`, `build_suggest_messages`)

- 시스템 프롬프트는 **한국어**로 쓴다(이 파일의 다른 프롬프트와 같은 이유: 모델은 불린 언어로 답한다).
- 지시: 학습자가 봇의 마지막 말에 대답할 수 있는 **완성 문장 2~3개**. **방향이 서로 달라야 한다** --
  예: 받아들이기 / 다른 것을 요청하거나 거절하기 / 되묻거나 질문하기. 같은 말을 표현만 바꾼 것은 안 된다.
  레벨에 맞춰 짧게(영어 12단어 이하, 일본어 30자 이하), 입말. `text`는 목표 언어, `meaning`은 한국어 한 줄.
  마크다운·이모지·괄호 설명 금지. 일본어면 `JAPANESE_SCRIPT_ONLY_RULE`을 붙인다.
- 문맥(상황·목표·주제·레벨·최근 대화)은 시스템 프롬프트 뒤 문단으로. 없는 조각은 줄째 뺀다(`_feedback_context`와 같은 원칙).
- 언어별 few-shot 1쌍: 봇 대사 하나 → 방향이 다른 세 줄 JSON. 사용자 턴 모양은 실제 쿼리와 같게
  (`상대방이 방금 한 말: "..."`).
- 스키마: `{"replies": [{"text": str, "meaning": str}]}`, `replies`는 required.
- `llm.chat_json(..., temperature=0.7)` -- 방향이 다른 줄을 얻으려면 교정(0.3)보다 높아야 한다.

### 서버 검증 (`app/api.py`: `_valid_replies`)

모델이 준 각 줄을 순서대로 거른다. 통과한 것만 보여준다.

1. `text`가 문자열이고 비어 있지 않다(앞뒤 공백 제거, 첫 줄만).
2. **목표 언어인가:** 한글이 한 자라도 있으면 탈락. 일본어는 가나가 한 자 이상 있어야 한다
   (가나 없는 한자만의 줄은 중국어일 수 있다). 영어는 라틴 글자가 있어야 한다.
3. **길이:** 영어 공백 기준 12단어 이하, 일본어 구두점 제외 30자 이하. 넘으면 탈락(잘라서 보여주지 않는다 -- 잘린 문장은 틀린 문장이다).
4. **중복:** `normalize(text)`가 앞서 통과한 줄과 같으면 탈락.
5. **봇 대사 되풀이:** `normalize(text)`가 봇 마지막 말과 같으면 탈락.
6. 최대 3줄까지만.

`meaning`:
- `_is_korean_meaning(meaning, source=text)`를 통과하면 그대로.
- 아니면 그 줄만 `_cached_translation(language, text)`로 다시 받는다(한글 검사·재시도·캐시가 이미 있는 경로).
- 그래도 None이면 `meaning: null` -- 화면이 `▸ 뜻` 버튼을 대신 준다(누르면 같은 `/translate`).

통과한 줄이 **2개 미만**이면 한 번 더 생성한다(같은 메시지, 재시도용 한국어 요청 한 줄을 덧붙이지 않고 그냥 다시 샘플링 -- 온도 0.7이라 다시 뽑는 것만으로 달라진다).
두 번째 결과는 첫 번째에서 통과한 줄과 합쳐 같은 검증(중복 포함)을 다시 거친다. 합쳐서 1개면 1개를 보여주고, 0개면 503.

### 음성

통과한 줄마다 `_speak(text, language)` → `audio_key`. **캐시 밖에서** 요청마다 붙인다 -- `_speak`는 디스크 캐시라 싸고, 캐시 안에 두면 TTS가 죽어 있던 순간의 null이 서버 재시작까지 남는다. TTS가 죽었으면 None, 클라이언트 `play(null, text)`가 브라우저 음성으로 읽는다
(대화 말풍선과 같은 규칙).

### 캐시

`(session_id, bot_message_id)`로 **성공한 응답만** 기억한다(`functools.lru_cache(maxsize=256)` 아래로 실패를 예외로 보내는 `_cached_translation`과 같은 모양).
같은 봇 대사에서 다시 누르면 같은 추천이 즉시 온다 -- 누를 때마다 바뀌면 "아까 그 문장"을 다시 볼 수 없다.
봇 메시지 id가 키에 있으므로 새 봇 대사는 자연히 새 추천이 된다. 되돌리기(`last-turn`)는 봇 메시지를 지우지 않으므로 캐시를 건드릴 필요가 없다.

## 화면

### 버튼

- `#controls` 줄의 `세션 끝내기` 앞에 `<button id="btn-suggest" class="ghost" type="button" hidden>💡 뭐라고 하지?</button>`.
  (`취소 (Esc)`는 듣는 동안에만 보이므로 그 옆에 두면 평소에는 외톨이가 된다.)
- **자유·수업 모드에서만 보인다**(대본 모드는 `hidden`).
- 대화창에 봇 말풍선이 하나도 없으면 눌러도 아무 일도 없다(자유·수업은 시작 대사가 항상 있어 실제로는 생기지 않는다).
- **턴 상태 머신(`turnstate.js`)과 독립이다.** 추천 요청은 녹음·전송·재생과 겹칠 자원이 없다 --
  봇이 말하는 중이나 듣는 중에도 누를 수 있다. 그래서 `syncControls`에 넣지 않는다.
- 요청 중에는 버튼을 비활성화하고(연타 방지) 끝나면 되돌린다.

### 결과 카드

- 누른 **그 순간의** 마지막 봇 말풍선을 붙잡고, 응답이 오면 그 말풍선 바로 뒤(`.chip-row`가 아니라 봇 말풍선 뒤)에 붙인다.
  응답이 오기 전에 다음 봇 대사가 와도 카드는 물어본 말풍선에 붙는다.
- 이미 카드가 붙은 말풍선에서 다시 누르면 새로 요청하지 않고 그 카드를 펼치거나 스크롤해 보여준다.
- 모양:
  ```
  ┌ 이렇게 말해볼 수 있어요 ─────────┐
  │ Sure, that works for me.       │  ← 누르면 재생
  │   좋아요, 저는 괜찮아요.          │
  │ Could we do Thursday instead?  │
  │   대신 목요일에 할 수 있을까요?     │
  └────────────────────────────────┘
  ```
- 줄마다 문장(`.suggest-line`)과 뜻(`.suggest-meaning`). 일본어는 문장에 `annotate`(후리가나·발음·▸ 뜻)를 그대로 적용한다.
  `meaning`이 null이면 뜻 줄 대신 `attachMeaning`의 `▸ 뜻` 버튼(영어), 일본어는 `annotate`가 그린 버튼이 그 역할을 한다.
- 문장 줄을 누르면 `play(audio_key, text)`. 뜻 버튼은 기존 `toggleMeaning`.
- **보내는 경로가 없다.** 입력칸에 넣지도 않는다 -- 학습자가 소리 내어 말해야 연습이다(음성 인식 결과를 편집하지 않게 한 결정과 같은 방향).
- 요청 중: 카드 자리에 "생각하는 중..."; 실패: "지금은 추천을 만들 수 없어요" + 다시 누를 수 있게 카드 제거.
- DB에 저장하지 않는다. 이어서 하기로 돌아오면 카드는 없고, 다시 누르면 된다(캐시가 살아 있으면 즉시).

## 테스트

### pytest (모델 목, 기본 스위트)

- `build_feedback_messages`: suggestion 정의·문맥 머리말 문구가 바뀌었고, few-shot 턴 모양은 그대로.
- `fixed` 되풀이 가드: 인용 구간이 `fixed`와 같으면 None; 포함만 하는 더 긴 대안은 살아남음; 중립 경로는 기존 동작 그대로; 문자열 아닌 suggestion에 예외 없음.
- `build_suggest_messages`: 문맥 조각이 있을 때만 줄이 생김, 일본어 규칙, few-shot 모양이 쿼리와 같음.
- `_valid_replies`: 한글 섞인 줄 · 가나 없는 일본어 줄 · 길이 초과 · 중복 · 봇 대사 되풀이 탈락, 3줄 상한.
- 뜻 대체: 한국어 아닌 meaning → `_cached_translation` 호출; 그것도 실패 → `meaning: null`.
- 재시도: 첫 결과 1줄 → 두 번째 호출, 합쳐 중복 제거; 둘 다 0줄 → 503; 모델 예외 → 503.
- 엔드포인트: 404 / 대본 400 / 끝난 세션 409 / 봇 대사 없음 409; TTS 실패 → `audio_key: null`.
- 캐시: 같은 봇 메시지에서 두 번째 요청은 모델을 부르지 않음; 새 봇 메시지는 새 호출; 실패는 캐시 안 됨.

### node

- 버튼: 자유·수업에서 보이고 대본에서 숨음; 봇 말풍선 없으면 비활성.
- 카드가 **요청 시점의** 봇 말풍선 뒤에 붙음(응답 전에 새 봇 말풍선이 추가돼도).
- 문장 줄 클릭 → `play(audio_key, text)`; 카드 안에 전송·입력칸 채우기 경로 없음.
- `meaning: null` → 뜻 버튼; 실패 → 문구 후 카드 제거; 같은 말풍선 재클릭 → 재요청 없음.

### engine (실제 모델, `-m engine`)

- **② `test_suggest_quality.py`:** 언어별 봇 대사 6개 내외(자유 시나리오·수업 대사 섞어서).
  - 통과한 줄이 2개 이상인 비율(문턱은 실측 뒤 그 아래로).
  - 방향 다양성: 한 응답 안의 줄들이 서로 다른 문장이고, 전부 같은 문형으로 시작하지 않음.
  - 한국어 뜻 비율(대체 번역 전 원본 `meaning` 기준으로도 따로 잰다), 중국어 누출 0(검증을 거친 최종 응답 기준).
- **① 전후 비교:** 같은 입력(학습자 문장 + 봇 직전 말 + 목표) 세트를 바꾸기 전/후 프롬프트로 돌려
  - `fixed` 되풀이율(가드 적용 전 원본 기준)이 줄었는지,
  - 상황 관련성: 표본을 사람이 읽고 판정(자동 판정은 하지 않는다),
  - 기존 `test_feedback_quality.py`가 그대로 통과하는지 -- **"오류를 여전히 잡는가"**. 조용해진 것을 나아진 것으로 착각하지 않는다.
  - 수치는 계획 문서가 아니라 커밋 메시지와 docstring에 기록한다.

### 일부러 부수기

새 가드(한글 검사, 가나 검사, 길이, 중복, fixed 되풀이, 캐시 키, 요청 시점 말풍선 고정)마다 한 번씩 꺼서 해당 테스트가 빨개지는지 확인한다.
