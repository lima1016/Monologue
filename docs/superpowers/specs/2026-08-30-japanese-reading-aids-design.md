# 일본어 읽기 보조 — 설계

2026-08-30. Phase 2 C단계(홈 화면) 직후, D단계(마이페이지) **이전**에 만든다.
E단계 쉐도잉도 대본을 읽는 모드라 여기에 기댄다.

## 왜 만드는가

학습자가 일본어 초보라 **대본 모드에서 일본어 대본을 읽을 수가 없다.** 대본 모드는
소리 내어 읽어야 하는 모드이므로, 못 읽으면 기능 자체가 성립하지 않는다. 같은 문제가
자유 상황극에도 있다 — 봇은 일본어로 말하고, 초보는 그것도 못 읽는다.

세 층을 겹쳐 보여주고, 학습자가 자라면 **위층부터 걷어낸다**:

- **후리가나** (한자 위 히라가나 루비) — 원문이 그대로 남아 한자를 눈에 익힌다
- **로마자** — 가나를 못 읽는 단계의 목발. 끌 수 있어야 한다
- **한국어 뜻** — 기본은 접힘. 먼저 짐작하고 확인하는 편이 남는다

후리가나만으로는 가나를 못 읽는 완전 초보에게 소용이 없고(위에 붙은 것도 가나다),
로마자만 쓰면 가나를 영영 안 보게 되고 발음이 영어식으로 굳는다. 그래서 겹치되
뺄 수 있게 한다.

## 범위

**적용되는 곳**

- 대본 패널의 모든 줄 (봇 줄, 내 줄 둘 다)
- 자유·수업 모드에서 **봇이 말하는 일본어 말풍선**
- 이어서 하기로 되살아난 대화의 봇 말풍선

**적용되지 않는 곳**

- 영어 세션 — 읽기 문제가 없다
- 홈 화면 시나리오 칩 제목, 리포트 예문 — 소리 내어 읽는 대상이 아니라 후리가나가 과하다
- 학습자가 입력한 문장 — 학습자가 쓴 것이다

## 핵심 결정

### 읽기는 사전에서, 뜻은 LLM에서

읽기 변환은 **형태소 사전**(`fugashi` + `unidic-lite`)으로 뽑는다. LLM은 한자 읽기를
그럴듯하게 지어내고, **틀린 읽기를 배우면 안 배우느니만 못하다.** 사전은 오프라인이고
무료이고 VRAM을 쓰지 않으므로, 이 프로젝트의 "실행 비용 0" 성질이 유지된다.

뜻은 사전이 주지 않는다. 문장 번역은 한자 읽기와 달리 LLM이 잘하는 일이므로 로컬 14b가
맡되, **펼칠 때만** 호출한다. 미리 번역하지 않는 이유는 두 가지다: 대본 8줄을 미리
번역하면 시작이 그만큼 느려지고, 학습자가 펼쳐보지 않을 줄까지 번역하게 된다.

### 저장하지 않고 렌더 시점에 만든다

읽기 보조는 **어디에도 저장하지 않는다.** 그래야 내장 대본과 LLM이 생성한 대본이 똑같이
동작하고, 이미 저장된 시나리오를 다시 만들 필요가 없다. 캐시는 프로세스 메모리에만 둔다 —
재시작하면 다시 만들면 그만이다.

### 전용 엔드포인트, 기존 payload 오염 없음

클라이언트가 일본어를 그릴 때마다 그리는 텍스트를 보내고 읽기를 받는다.

대안은 줄을 실어 나르는 payload 넷(`POST /sessions`, `/chat`, `/sessions/{id}`, 재생)에
각각 `reading` 필드를 붙이는 것이었다. **거부한다** — 네 곳을 다 기억해야 하고, 이
프로젝트는 이미 정확히 그 실수를 했다(이어서 하기가 목표 패널을 빠뜨렸다). 전용
엔드포인트는 이어서 하기를 **공짜로** 덮는다. 재생이 `addMessage`를 그대로 쓰기 때문이다.

브라우저 형태소 분석(`kuromoji.js`)도 거부한다. 수 MB짜리 사전을 하나 더 들여오고,
서버 사전과 결과가 갈릴 수 있다.

## 백엔드

### `app/reading.py` (신규)

```
analyse(text: str) -> list[dict]
```

토큰 하나는 이렇게 생겼다:

```json
{
  "surface": "食べる",
  "reading": "たべる",
  "romaji": "taberu",
  "parts": [ {"text": "食", "ruby": "た"}, {"text": "べる", "ruby": null} ]
}
```

`parts`가 **루비가 표기의 어느 부분 위에 앉는지**를 표현한다. 필드 하나로 `ruby: "た"`만
주면 클라이언트는 그것을 `食` 위에 올릴지 `食べる` 전체 위에 올릴지 알 수 없다 — 그래서
분할을 서버가 확정해서 넘긴다. 정렬 규칙을 아는 쪽은 서버 하나뿐이어야 한다.

이 모양은 세 경우를 모두 균일하게 담는다:

| 경우 | `parts` |
|---|---|
| `食べる` (한자 한 덩어리) | `[{食, た}, {べる, null}]` |
| `よやく` (한자 없음) | `[{よやく, null}]` |
| `取り引き` (폴백, 전체 위에 통째) | `[{取り引き, とりひき}]` |

클라이언트는 `parts`를 순서대로 그리면서 `ruby`가 있으면 `<ruby>`로 감싸고 없으면 평문으로
둔다 — 분기 하나로 세 경우가 다 처리된다.

분석 자체가 실패하면 `reading`과 `romaji`는 `None`이고 `parts`는 `[{text: 원문, ruby: null}]`
하나다. 클라이언트가 별도 분기 없이 평문을 그리게 된다.

**절대 raise하지 않는다.** 사전이 없거나 분석이 실패하면 위의 평문 토큰 하나를
돌려주고, 클라이언트는 평문을 그린다. `_speak`(`app/api.py:148`)가 TTS 장애에 대해 이미
그렇게 하고 있고, 읽기 보조도 같은 계약을 물려받는다 — **줄이 비는 일은 없다.**

### 후리가나 정렬 규칙

사전은 토큰의 **읽기 전체**를 준다: `食べる` → `タベル`. 그대로 올리면 이미 읽을 수 있는
`べる` 위에까지 가나가 붙어 오히려 읽기 어려워진다.

규칙:

1. 카타카나 읽기를 히라가나로 바꾼다
2. 표기와 읽기에서 **앞뒤로 일치하는 가나를 벗겨낸다**
3. 남은 표기가 **한자 한 덩어리**면, 그 위에 남은 읽기를 루비로 올린다
4. 남은 표기에 한자가 없으면 루비를 붙이지 않는다
5. 남은 한자 덩어리가 **둘 이상**이면(`取り引き` 등) 토큰 **전체** 위에 읽기를 통째로 올린다

5번 폴백을 명시하는 이유는, 여기서 영리해지려다 **틀린 읽기**를 만드는 것이 이 기능의
전제를 무너뜨리기 때문이다. 통째로 올린 읽기는 정확하지 않아도 정직하며 여전히 읽을 수
있다.

로마자는 **헵번식**이다 (`し` → `shi`, `つ` → `tsu`). 일본어 교재와 도로 표지판이 쓰는
방식이라 앱 밖에서도 통한다.

### `POST /api/reading`

요청 `{language, texts: [str, ...]}` → 응답 `{readings: [[token, ...], ...]}`

- `language`가 `ja`가 아니면 400
- **줄 하나가 아니라 그리는 줄 전부를 한 번에** 받는다. 대본 8줄이면 요청 하나
- **크기 제한이 있는** 프로세스 내 LRU 캐시. 읽기는 결정적이고 텍스트는 반복된다
  (이어서 하기 때 같은 줄이 다시 온다). 캐시는 반드시 상한이 있어야 한다 — 자유 대화는
  매 턴 새로운 문장을 만들어내므로 무제한 캐시는 세션이 길어질수록 자라기만 한다

### `POST /api/translate`

요청 `{language, text}` → 응답 `{meaning: str}`

- 뜻을 **펼칠 때만** 호출된다
- `language`가 `ja`가 아니면 400 — `/api/reading`과 같은 규칙
- `prompts.py`에 짧은 프롬프트 하나를 더한다: 자연스러운 한국어 한 줄, 설명 금지
- 크기 제한이 있는 LRU 캐시. 같은 줄을 다시 펼치거나 이어서 하기로 되돌아와도 다시
  번역하지 않는다
- LLM 실패 시 **503**. 클라이언트는 "뜻을 가져오지 못했습니다"를 보여주고, 줄은 그대로 둔다

### `app/api.py:243` — 내 줄에도 음성을 붙인다

지금은 봇 줄에만 음성을 합성한다:

```python
key = _speak(line["text"], payload.language) if line["speaker"] == "bot" else None
```

이 조건을 지운다. **내 차례 줄을 미리 듣고 따라 읽는 것**이 클릭해서 듣기의 목적이므로,
내 줄에 음성이 없으면 기능이 반쪽이 된다. 대본은 8줄 남짓이고 TTS는 캐시되므로 비용은
무시할 만하고, 기존의 선합성 패턴과도 맞는다.

## 프론트엔드

### `static/js/reading.js` (신규) — 덧입히는 층

**먼저 그리고 나중에 덧입힌다.** 기존 코드가 평문을 그대로 그리고, `/api/reading` 응답이
도착하면 그 위에 루비와 로마자를 얹는다.

```
1. 그린다      いらっしゃいませ
2. 덧입힌다     いらっしゃいませ
                irasshaimase
                ▸ 뜻
```

이 순서면 사전이 죽어도, 요청이 실패해도, 느려도 **줄은 항상 읽을 수 있는 상태로 남는다.**
덧입히기가 안 될 뿐이다. 이것이 이 기능의 가장 중요한 실패 모드이며, 테스트로 고정한다.

후리가나는 `<ruby>食<rt>た</rt></ruby>` 로 그린다 — 브라우저 기본 기능이고 라이브러리가
필요 없다.

### 붙는 곳

| 어디 | 어떻게 |
|---|---|
| 대본 패널 `<ol>` | `startScript` (`session.js`) |
| 봇 말풍선 | `addMessage('bot', …)`, `state.language === 'ja'`일 때만 |
| 이어서 하기 재생 | **자동** — 재생이 `addMessage`를 그대로 쓴다 |

### 클릭해서 듣기 — 대화창에는 충돌이 있다

**대본 패널**: 줄을 누르면 `play(line.audio_key, line.text)`. 봇 줄과 내 줄 **둘 다**.

**대화창**: 내 말풍선 클릭은 **이미 되돌리기에 잡혀 있다**(`main.js`의 `conversation`
핸들러 → `undoLastTurn`). 따라서

- 대화창에서는 **봇 말풍선만** 클릭해서 듣기
- 내 말풍선은 되돌리기, `▶ 내 발음`(내 녹음 재생)도 그대로
- 대본 패널에는 되돌리기가 없으므로 양쪽 다 클릭 가능

봇 말풍선은 이미 음성 키를 받아오지만(`opening_audio`, `audio_key`) 지금은 재생하고
버린다. `addMessage` 때 `data-audio-key`로 말풍선에 붙여두면 다시 들을 수 있다.

"따라 읽기 전에 미리 듣기"라는 목적은 대본에서 온전히 살아 있으므로, 대화창의 이 제약은
받아들인다.

### 설정

설정 대화상자에 체크박스 둘 — **후리가나**, **로마자**. 기본은 둘 다 켜짐, 뜻은 접힘.

저장은 기존 설정 테이블(`get_setting`/`set_setting`)에 둔다. 음성 설정이 이미 그 길로
서버에 저장되고 있으므로 같은 패턴을 따른다. 일본어에만 영향을 준다는 것을 라벨에 적는다.

끄면 클라이언트가 그리지 않을 뿐 서버 응답은 같다. **로마자를 끄는 것은 "가나를 읽을 수
있게 됐다"는 신호**이고, 나중에 후리가나까지 끄면 원문만 남는다 — 목발을 순서대로
치우는 설계 그대로다.

## 테스트

**Python**

- 정렬, `parts`로 확인한다: `食べる` → `[{食, た}, {べる, null}]`; `よやく` →
  `[{よやく, null}]`; `取り引き` → `[{取り引き, とりひき}]`
- 사전을 못 쓸 때 → 예외가 아니라 평문 토큰 하나
- `POST /api/reading` — 여러 줄 한 번에, `ja`가 아니면 400, 두 번째 호출이 캐시를 탄다
- `POST /api/translate` — LLM 실패 시 503, 캐시가 두 번째 호출을 막는다
- 대본의 **내 줄에도** `audio_key`가 채워진다

**Node** (C단계의 DOM 셔임 위에)

- 루비가 실제로 그려진다
- **`/api/reading`이 실패해도 평문이 그대로 남는다** — 가장 중요한 테스트
- 뜻 토글, 로마자 끄기
- 새 모듈이 들어와도 모듈 그래프 평가가 깨지지 않는다

## 위험

**`fugashi` 설치.** C 확장이라 Windows / 파이썬 3.13용 휠이 없으면 컴파일러가 필요하다.
**구현 첫 단계에서 이것부터 확인하고**, 안 되면 거기서 멈추고 보고한다. 대안은
`SudachiPy`(순수 파이썬 계열, 사전이 더 큼)와 `pykakasi`(가볍지만 정확도가 낮음)이며,
막히면 다시 정한다. 설계의 나머지는 이 선택에 의존하지 않는다 — `reading.analyse`의
계약만 지키면 그 안이 무엇이든 상관없다.

## 하지 않는 것

- 단어별 사전 뜻(JMdict) — 문장의 뜻을 알려주지 않고, 한국어 뜻은 성김새가 많다
- 읽기 보조를 시나리오에 저장하는 것
- 영어 세션에 적용하는 것
- 홈 화면 칩과 리포트 예문에 적용하는 것
- 악센트 표시, 피치 곡선 — 초보 단계에서 과하다
