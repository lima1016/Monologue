# Monologue — 쉐도잉 설계 (Phase 2 E, 첫 번째)

- 날짜: 2026-09-19
- 상태: 사용자 승인("스펙으로 쓰고 바로 시작해줘")
- 선행: 마이페이지(`170df20`). 원래 Phase 2 설계(`2026-08-29-monologue-phase2-design.md` "새 모드 → 쉐도잉")를 지금 코드(Whisper, 테마 라이브러리, 복습 목록)에 맞게 구체화한다.
- E의 두 번째(1분 말하기)는 별도 스펙.

## 원칙

- **소리 먼저, 글자 나중.** 스크립트 모드는 글자를 보고 읽는 낭독이다. 쉐도잉은 원어민 소리를 먼저 듣고 바로 따라 말한 뒤 글자로 확인한다.
- **모든 줄을 따라 한다.** 봇 줄·내 줄 구분 없이 16줄 전부.
- **넘어가는 건 학습자가 정한다.** 자동 넘김 없음. 두 녹음을 비교해 들을 시간을 준다.
- **문법 채점 안 함.** 앱이 준 문장이다. "대본과 같았나"만 본다.
- 사용자 규칙: 오래 걸리는 대기는 무엇을 하는 중인지 보이고, 단계가 바뀌어도 자리·크기가 튀지 않는다.

## 들어가는 곳

- 홈 모드 카드에 4번째 `쉐도잉` — 설명 `원어민 소리를 듣고 바로 따라 말하기`. `data-mode="shadow"`.
- 누르면 `#pick`으로 간다. 테마·대본은 스크립트와 **같은 라이브러리**(준비 판정도 스크립트와 같다: `ready.script > 0`). `#pick` 제목은 `쉐도잉`.
- 시작 대기 문구: `음성 준비 중...`(16줄 음성 선합성).
- 클라이언트 모드 표현: 서버 모드는 `script`, 여기에 `shadowing: true`. 클라이언트는 `state.mode = 'script'` + `state.shadowing = true`로 들고 다닌다. 스크립트용 분기(채점 안 함, 전송 경로 등)를 그대로 물려받기 위함. 홈 카드의 `shadow`는 `#pick` 진입과 표시용일 뿐 서버로 가지 않는다.
- 홈 "오늘의 추천"의 시작 버튼에는 넣지 않는다(범위 밖).

## 세션 화면

스크립트 세션 화면을 쓰고 다음만 다르다.

### 대본 칸 (오른쪽 `#side-panel`, 제목 `쉐도잉`)

- 줄마다 `봇`/`나` + 가린 자리(`●●●●●`, 글자 수와 무관하게 고정 폭). 현재 줄 강조.
- 끝낸 줄(한 번이라도 공개된 줄)은 원문이 보인다. 일본어는 기존 읽기 보조(`annotate`), 영어는 기존 뜻 보기(`attachMeaning`).

### 지금 줄 카드 (`#shadow-card`, 대화 영역 위치)

한 장의 카드가 단계를 돈다. **카드의 자리와 최소 높이는 고정**, 단계 전환은 내용만 짧은 페이드(기존 `.is-invisible`/`setShown` 방식). 봇/나 말풍선은 쉐도잉에서 그리지 않는다.

1. **듣기** — 줄 번호 `3 / 16`, 원어민 음성 자동 재생. 버튼: `다시 듣기`, `천천히 듣기`(0.75배, 한 번), `글자 보기`.
   - `글자 보기`: 원문을 보이게 하고 그 줄을 `peeked`로 표시. 되돌릴 수 없다(한 번 보면 봤다).
2. **말하기** — 아래 큰 마이크(기존 받아쓰기 흐름 그대로: 브라우저 미리보기 + Whisper 최종, Esc 취소). 받아쓰는 동안 카드에 `받아쓰는 중...`.
   - 못 알아들음(빈 결과): 서버에 보내지 않고 `못 알아들었어요. 다시 해보세요`, 단계는 말하기 그대로.
3. **공개** — 원문(읽기 보조 포함), `내 말: "…"`, 판정 `✓ 대본과 같아요` / `✗ 조금 달라요`, 글자를 봤으면 꼬리표 `글자 보고 함`. 버튼 `▶ 원어민`, `▶ 내 발음`, `다시 하기`, `다음 줄 →`.
   - `다시 하기`: 원문은 계속 보인 채로 말하기로 돌아간다. 저장은 마지막 시도가 앞 시도를 덮어쓴다.
   - 저장 실패: `저장하지 못했어요` 알림, 단계는 말하기로 되돌림(내 말은 카드에 남긴다).
4. **다음 줄** — 대본 칸에 그 줄 공개, 다음 줄 듣기로.

- 마지막 줄 공개 뒤 `다음 줄 →` 자리에 `끝! 리포트 보기` — 기존 세션 끝내기 흐름.
- 쉐도잉에서는 되돌리기(undo)와 `다음`(스크립트용), 텍스트 입력, `💡 뭐라고 하지?`를 숨긴다.
- **이어하기 없음.** 스크립트 세션은 이미 이어하기 대상이 아니다(`resumable_session`이 제외). 쉐도잉도 그대로 따른다.

## 리포트

- LLM을 부르지 않는다. 숫자만:
  - `따라 한 줄 <n>/<전체>`, `대본과 같음 <m>`, `글자 보고 함 <p>`, `<분>분`.
- `어려웠던 줄`(달랐던 줄 또는 글자를 본 줄): 원문 / 내 말 / `▶ 원어민` `▶ 내 발음`.
- 어려웠던 줄이 있으면 `이 줄들은 내일 복습에 나와요`. 없으면 `전부 대본대로 따라 했어요 🎉`.
- 요약·약점·표현·다음에 해볼 것 칸은 쉐도잉 리포트에서 숨긴다.

## 홈·마이페이지

- 이번 주·최근 연습·지난 기록에 쉐도잉 세션이 들어간다. 표시 `쉐도잉`(스크립트의 `대본` 자리). 지난 기록 줄: `따라 한 줄 <n> · 쉐도잉`.
- 레벨·정확도·약점에는 들어가지 않는다 — 쉐도잉 줄의 `ok`는 NULL이고 세션 `level`도 NULL이다(아래).
- 복습 카드: 쉐도잉에서 온 문장은 태그 칩 자리에 `쉐도잉` 꼬리표. `내가 한 말`(취소선)과 `고친 문장` 대신 같은 자리에 내 말 / 대본 줄을 보여 준다(데이터 모양이 같아 그대로 동작, 문구만).

## 데이터 (스키마 v6 → v7)

머지 전에 본 DB 백업.

- `sessions.shadowing INTEGER NOT NULL DEFAULT 0`
- `messages.matched INTEGER` — 쉐도잉 줄만. 대본과 같았으면 1, 아니면 0.
- `messages.peeked INTEGER` — 쉐도잉 줄만. 글자를 봤으면 1.

쉐도잉 한 줄 = `messages` 한 행: `speaker='user'`, `text`=내 말, `fixed`=대본 줄, `script_index`=줄 번호, `ok`/`tag`/`correction`/`suggestion`=NULL. 기존 `UNIQUE(session_id, script_index)`가 줄당 한 행을 보장하고, 다시 하기는 같은 행을 갱신한다(행 id 유지 — 녹음이 id에 붙으므로).

`ok`가 NULL이라 `session_stats`의 wrong/tags, `home_stats`의 fixed_total·top_tags, `accuracy_since`, `stable_level`에 섞이지 않는다. `week_turns`(말한 문장 수)에는 들어간다 — 실제로 말한 문장이므로 맞다.

## API

- `POST /sessions` — `shadowing: bool = false` 추가. `mode='script'`일 때만 허용(다른 모드면 400). 응답은 스크립트와 같고 `shadowing: true`가 붙는다. 모든 줄 음성 선합성은 이미 스크립트가 한다.
- `POST /sessions/{id}/shadow-line` `{index: int, text: str, peeked: bool}` → `{message_id, matched}`
  - 400: 쉐도잉 세션 아님, 빈 text, 범위 밖 index. 404: 없는 세션. 409: 끝난 세션.
  - `matched`는 **서버가** `text_match`(파이썬 쌍둥이, `match.js`와 파리티 테스트로 묶임)로 `text` 대 대본 줄을 판정. 클라이언트도 같은 `matches()`로 화면 판정을 먼저 그리지 않고 서버 응답을 쓴다(한 곳의 판정).
  - 같은 index 재전송: 행을 갱신(text, matched, peeked는 **한 번이라도 봤으면 1 유지** — OR). 레이스에도 한 행.
  - 녹음은 기존 업로드 경로로 `message_id`에 붙는다(다시 하기면 덮어쓴다).
- `POST /sessions/{id}/end` — 쉐도잉이면:
  - LLM 호출 없음. `report` JSON = `{"kind": "shadow"}`(숫자는 읽을 때 계산), `level` NULL.
  - 복습 넣기: `matched = 0 OR peeked = 1`인 줄을 내일 날짜로 `enqueue_review`.
  - 응답: `{kind: "shadow", level: null, stats, shadow: {lines, done, matched, peeked, hard: [{index, said, target, message_id, audio_key}]}}`.
- `GET /sessions/{id}/report` — 쉐도잉이면 같은 모양(`shadow` 포함, `mode: 'script'`, `shadowing: true`).
- `GET /sessions/history`, 홈 최근 연습 — 행에 `shadowing` 추가.
- `due_reviews` — 행에 `shadowing`(원 세션의 값) 추가.
- 되돌리기(`DELETE /sessions/{id}/last-turn`) — 쉐도잉 세션이면 400(화면에도 없다).

## 화면 코드

- `static/js/shadow.js` 새 모듈: 지금 줄 카드의 단계 상태와 그리기만. 세션 시작·끝내기·마이크·업로드는 `session.js`의 기존 함수를 쓴다(`session.js`는 쉐도잉 분기로 들어가는 입구만).
- `audio.js` `play(key, text, onDone, {rate})` — 재생 속도 옵션(`천천히 듣기`).
- `index.html`: 홈 4번째 카드, `#shadow-card` 틀.
- 스타일: 기존 토큰·컴포넌트 재사용.
