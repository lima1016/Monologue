# Monologue 시각 아이덴티티 재설계 — 설계

## 개요

매일 여는 화면이 "촌스럽고 뭐 없어 보인다"는 사용자 판단에서 출발한다. 색·글꼴·배치를
다시 잡되, **이름(Monologue)은 유지**하고 **혼자 쓰는 앱**이라는 전제를 지킨다.

브레인스토밍에서 실제 화면 목업을 띄워놓고 고른 결과:

- 분위기: **A — 따뜻하고 다정하게** (미색 종이 + 테라코타). 차분(B)·또렷(C) 안은 탈락
- 홈: **B — 넓게** (2단, 왼쪽 할 일 / 오른쪽 맥락)
- 리포트: **B — 두 칸** (2단, 왼쪽 본문 / 오른쪽 요약·약점)

## 목표

- 맑은 고딕 폴백을 끝낸다. 촌스러움의 가장 큰 몫이 여기 있다
- 홈·리포트가 넓은 화면에서 비어 보이지 않게 한다
- 상자 개수를 줄이고 크기·무게 차이로 위계를 만든다
- 교정 피드백이 "혼내는 색"으로 돌아가지 않게 한다

## 비목표

- **이름·로고·상표·랜딩 페이지** — 혼자 쓰는 앱이다. 로고 사용 규정 같은 것은 만들지 않는다
- **세션 화면 배치 변경** — 타이포·색은 토큰으로 자동으로 따라온다. 배치는 그대로 둔다
- **`ui-ux-pro-max:brand` 스킬의 `assets/design-tokens.{json,css}` 도입** — 아래 참조
- **LLM 프롬프트·스키마 변경** — 아래 "리포트 헤드라인" 참조

### 토큰 소스를 둘로 만들지 않는다

`brand` 스킬의 `sync-brand-to-tokens.cjs`는 `docs/brand-guidelines.md`를 소스로 삼아
`assets/design-tokens.css`를 생성한다. 이 프로젝트의 실질적 소스는 이미
`static/css/tokens.css`이고, 거기엔 값마다 *왜 그 값인지*가 주석으로 붙어 있다
(`--surface-sunken`이 1.04:1이라 말풍선이 맨 텍스트로 보였던 기록, 다크에서
`--on-accent`를 흰색이 아니라 근접 검정으로 뒤집은 계산 등).

생성 파일을 추가하면 토큰 소스가 둘이 되고, 근거 주석은 생성기가 보존해주지 않는다.
**`static/css/tokens.css`가 단일 소스로 남는다.**

## A. 토큰과 글꼴

### 글꼴 — Pretendard, 자체 호스팅

현재 `body { font-family: system-ui, ... }`는 윈도우에서 한글이 **맑은 고딕**으로 떨어진다.
Pretendard로 바꾼다.

**CDN을 쓰지 않고 `static/fonts/`에 넣는다.** 이 앱은 Ollama도 VOICEVOX도 로컬로 도는
오프라인 앱이다. 글꼴만 인터넷에 의존하면, 네트워크가 끊긴 날 앱은 멀쩡히 돌면서 글꼴만
맑은 고딕으로 돌아간다 — 고치려는 문제가 조용히 되살아나는 실패 방식이다.

- `PretendardVariable.woff2` 한 파일(가변 폰트, 45~920 weight)을 받아 `static/fonts/`에 둔다
- `@font-face`에 `font-display: swap`과 실물 폴백 스택을 준다
- 파일 크기는 받아서 확인하고, 1.5MB를 넘으면 한글 서브셋을 뜬다.
  `.gitignore`의 `engines/` 제외 규칙은 수백 MB 모델 가중치를 겨냥한 것이라
  이 파일에는 적용하지 않는다 — 커밋한다

```css
--font-sans: Pretendard, system-ui, -apple-system, "Segoe UI", sans-serif;
```

`--on-accent`가 다크에서 **근접 검정으로 뒤집히는 규칙은 기존 파일에서 그대로 가져온다.**
`--accent`는 두 스킴에서 명도가 반대로 간다(라이트=진한 테라코타, 다크=밝은 살구). 다크에서
`--on-accent`를 흰색으로 두면 시작 버튼·이어하기 카드·마이크 글리프가 전부 씻겨 보인다.
`--accent` 위에 그려지는 모든 것이 이 토큰 하나를 쓰므로 함께 뒤집힌다.

```
--text-xs: 11.5px;  --text-sm: 13px;    --text-base: 15px;

```

`--text-3xl`은 홈 인사말과 리포트 헤드라인 전용이다. 기존 스케일에서 가장 큰 값이
25px이라 "가장 큰 것"과 "본문"의 차이가 부족했고, 이것이 위계 없음의 절반이었다.

## B. 홈

`1fr var(--aside-w)` 2단 그리드, `max-width: 1100px`.

- **왼쪽 (할 일):** 날짜 → 인사말(`--text-3xl`) → 한 줄 요약 → 입력창 → 칩 →
  모드 세그먼트 → 시작 버튼
- **오른쪽 (맥락):** 이어하기 · 이번 주 · 최근 연습

바꾸는 것:

- 모드 3개: 개별 상자 → **세그먼트 하나**. 상자 셋이 시작 버튼과 무게를 다투던 문제가 사라진다
- 칩: 테두리 상자 → 조용한 텍스트 버튼
- 통계: 테두리 상자 → 오른쪽 패널로 이동, 연속 학습일은 7칸 점
- 이어하기: 통짜 테라코타 → 왼쪽 3px 액센트 막대. **시작 버튼이 화면에서 가장 센 것이 된다**

`.recommend`(추천 문구)는 요소를 유지하되 인사말 아래로 옮긴다. 액센트 계열을 쓰는 기존
판단은 그대로다 — 추천은 초대이지 교정이 아니다.

### 첫 실행 — 빈 오른쪽 칸

**이 설계에서 가장 깨지기 쉬운 지점이다.** 지금 `#home`은 flex 컬럼이라
`[hidden] { display: none !important }`가 요소와 gap을 함께 지운다. 첫 실행에서
`#resume-card`·`#recommend`·`#home-stats`가 전부 숨겨져도 구멍이 남지 않는 건 그 덕이다.

grid로 가면 다르다. 오른쪽 트랙은 자식이 전부 숨겨져도 **330px를 그대로 차지한다.**
설치 첫날 화면이 왼쪽으로 쏠린 채 오른쪽이 텅 빈다.

**규칙:** `loadHome()`이 오른쪽 칸에 보이는 패널이 하나도 없으면 `#home`에 `.no-aside`를
붙이고, 그 클래스는 `grid-template-columns: 1fr`로 접는다. 패널이 하나라도 생기면 뗀다.

이 경로에는 테스트를 붙인다 (아래 E).

### 반응형

`max-width: 880px`에서 1단. 오른쪽 패널은 시작 버튼 **아래**로 내려간다 — 맥락이 할 일보다
먼저 나오면 안 된다.

## C. 리포트

`1fr var(--aside-w)` 2단, `max-width: 1060px`. 홈과 같은 토큰을 쓴다 —
두 화면의 오른쪽 칸이 다른 너비일 이유가 없다.

- **왼쪽:** 시나리오 라인 → 헤드라인 → 오늘 잘한 것(인용 스타일) → 고친 표현 → 새 세션
- **오른쪽:** 이번 세션 숫자 · 자주 놓치는 것 · 다음에 해볼 것

고친 표현은 **위아래를 뒤집는다.** 지금은 취소선 친 원문과 고친 문장이 비슷한 무게다.
새 배치에서 원문은 작고 흐리게(`--text-sm`, `--text-faint`), 고친 문장은 `--text-lg`에
`font-weight: 600`, `--suggest-ink`. 읽어야 할 것은 고친 쪽이다.

### 리포트 헤드라인 — LLM에 새 필드를 요구하지 않는다

목업의 "오늘 12턴을 끝까지 영어로 밀고 갔어요"는 LLM이 쓴 문장처럼 보이지만, **프롬프트와
응답 스키마는 건드리지 않는다.** 리포트 프롬프트는 여러 라운드에 걸쳐 다듬어져 지금
한국어로 잘 나오고 있고(`build_report_messages`), 필드를 추가하면 그 품질이 회귀할 위험이
붙는다. 이 프로젝트에는 "프롬프트 변경은 실제 모델로 전후 비교해야 한다"는 기록이 이미 있다.

헤드라인은 **이미 있는 숫자로 클라이언트에서 조립한다**: 시나리오 제목 + 턴 수.
예) `오늘 12턴을 주고받았어요.` LLM이 쓴 산문은 그 아래 "오늘 잘한 것" 인용 자리에
지금처럼 들어간다.

## D. 서버

### `home_stats` — `top_tag` → `top_tags`

`db.home_stats()`는 이미 태그별 집계를 하고 있다. 지금은
`GROUP BY m.tag ORDER BY n DESC LIMIT 1`로 하나만 뽑아 `top_tag`로 내보낸다.
**`LIMIT 3`으로 바꾸고 개수를 함께 싣는다.**

```
top_tags: [{"tag": "과거 시제", "n": 7}, {"tag": "관사", "n": 4}]
```

**3회 미만 태그는 계속 제외한다.** 기존 코드의 판단을 그대로 지킨다 — "한 번의 실수로
매긴 약점은 사실인 척하는 추측이다". 목업에는 `전치사 1회`가 그려져 있었는데 그것은 이
규칙 위반이며 구현하지 않는다. 3회 이상이 하나도 없으면 패널 자체를 숨긴다.

기존 `top_tag` 소비처를 전부 `top_tags`로 옮긴다.

### `recent_sessions(language, limit=3)` — 신설

`db.list_sessions(limit=20)`이 있지만 언어 필터도 세션별 집계도 없다. 새로 쓴다.
끝난 세션만, 최신순으로: 시나리오 제목 · 종료 시각 · 그 세션에서 고친 개수.

**등급(`B+`, `A-`)은 넣지 않는다.** 목업에 그려져 있었지만 두 가지로 잘못됐다.
그런 데이터가 없고, 더 중요하게는 **이 프로젝트가 이미 반대로 결정했다.** `db.py`의
`stable_level()` 주석에 세션별 레벨 추정을 Phase 2C에서 일부러 삭제했다고 적혀 있다 —
"한 세션의 추정치는 노이즈다. 같은 전사를 세 번 돌리면 세 번 다르게 나온다."
화면을 채우려고 이미 내린 결론을 되돌리지 않는다.

세션에 제목이 없을 수 있다(자유 입력 시나리오). 그 경우 서버가 `goal`의 첫 줄로 대체하고,
그것도 없으면 `"자유 대화"`를 쓴다. 표시 문자열을 항상 서버가 정하는 이유는, 클라이언트가
빈 값을 만나 자기 나름대로 채우기 시작하면 같은 빈칸이 화면마다 다르게 메워지기 때문이다.

## E. 회귀 방지

이 프로젝트에는 **"초록은 증거가 아니다"**가 반복 기록돼 있다. 전체 리뷰가 Critical을
찾았을 때 스위트는 전부 초록이었다. 이번 작업은 특히 그 실패에 취약하다:
**정의되지 않은 `var()`는 에러가 아니라 무효다.** 토큰 이름을 하나 놓치면 CSS는 조용히
무너지고 테스트는 초록으로 남는다.

1. **토큰 이름 대조 테스트 (신규).** `tokens.css`가 정의하는 이름 집합과, 나머지 CSS가
   `var()`로 참조하는 이름 집합을 뽑아 대조한다. 참조되는데 정의 안 된 이름이 있으면 실패.
   이번 작업의 실패 방식을 정확히 겨냥한 유일한 계기다
2. **라이트/다크 대칭 테스트 (신규).** 라이트 블록이 정의한 색 토큰 중 다크 블록에서
   재정의되지 않은 것을 보고한다. 기존 파일의 규칙("색을 다크 블록 안에서만 정의하지 말 것")의
   반대 방향을 지킨다
3. **홈 첫 실행 테스트 (신규, node).** 이어하기·통계·최근 기록이 모두 없을 때 `#home`에
   `.no-aside`가 붙는지, 하나라도 생기면 떨어지는지
4. **`home_stats` 테스트 갱신.** `top_tags`가 3회 미만을 거르는지, 최대 3개인지,
   빈 배열을 돌려줄 수 있는지
5. **`recent_sessions` 테스트 (신규).** 언어 필터, 끝난 세션만, 제목 없는 세션의 표시 문자열
6. **기존 스위트 유지.** 기준선은 pytest 293 passed / 8 deselected, node 61

**각 테스트는 일부러 부숴서 빨개지는지 확인한다.** 이 프로젝트에서 벙어리 하네스와
"앞 테스트 실패 덕에 통과하던 테스트"가 실제로 잡힌 적이 있다.

### 눈으로 확인해야 하는 것

테스트가 볼 수 없는 것들이다. 브라우저에서 직접 본다:

- 6가지 조합 (2언어 × 3모드)에서 홈·세션·리포트
- **다크 모드** — 특히 `--on-accent` 뒤집기가 실제로 먹는지
- 일본어 세션에서 후리가나·로마자가 얹힌 줄 간격 (`line-height: 2.1` 규칙이
  새 타입 스케일에서도 맞는지)
- 첫 실행 상태 (DB 복사본을 비워서)
- 880px 아래 1단 전환

## 위험

| 위험 | 대응 |
|---|---|
| 정의 안 된 `var()`가 조용히 무효화 | E-1 대조 테스트 |
| 첫 실행에 오른쪽 칸이 유령으로 남음 | `.no-aside` + E-3 |
| 폰트 파일이 커서 첫 로드가 느려짐 | `font-display: swap`, 1.5MB 초과 시 한글 서브셋 |
| 일본어 루비 줄 간격이 새 스케일에서 깨짐 | 눈으로 확인 목록에 포함 |
| 리포트 품질 회귀 | 프롬프트·스키마를 아예 건드리지 않는다 (C 참조) |
| 다크에서 액센트 위 글자가 씻겨 보임 | `--on-accent` 뒤집기 규칙 승계, 눈으로 확인 |
