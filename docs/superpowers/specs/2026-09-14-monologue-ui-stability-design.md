# Monologue — 화면 안정화 설계 (튀지 않는 전환)

- 날짜: 2026-09-14
- 상태: 사용자 승인("그대로 쭉 진행")
- 사용자: "모든 페이지에서 버튼 눌렀을 때 화면 전환이나 format 같은 게 너무 훅훅 바뀌는 게 보여서 조잡해 보여. 크기가 갑자기 늘어났다 줄어들었다 하는 게 눈에 보여."

## 측정·코드에서 찾은 원인

1. 화면 교체(`router.show`)가 `hidden` 토글로 한 프레임에 통째로 바뀐다.
2. `loadHome`이 요청 전에 이어서 하기·이번 주·추천·최근 테마 등을 **숨겼다가** 응답 뒤 다시 보인다 → 언어 전환·홈 복귀마다 접혔다 펴진다(측정: 언어 전환 때 이번 주 카드 85px 이동).
3. `#notice`가 문서 흐름 안에 있어 알림 한 줄에 페이지 전체가 밀린다.
4. 세션 `#mic-dock`: `#btn-cancel`이 듣는 동안만 `display`되고, `#mic-hint` 길이가 변하고, `#thinking`이 켜지고 꺼져 대화창 높이가 출렁인다.
5. 로딩 자리(`불러오는 중...` 한 줄, `테마 불러오는 중...`)가 실제 내용보다 훨씬 작다.
6. 글자가 바뀌는 버튼(`▶ 듣기` ↔ `음성 준비 중...`, `시작`)의 폭이 변한다.
7. 나타났다 사라지는 줄(`#start-status`, `#library-progress`, `#today-alt`)이 아래를 민다.

## 규칙 (앞으로의 모든 화면에도 적용)

- **R1 화면 전환:** 들어오는 화면에 150ms **오퍼시티 페이드만** 준다 -- opacity fade only — a transform on a screen would break its fixed/sticky children (스크린 요소 자체에 transform을 쓰면, 애니메이션이 도는 동안 그 화면이 `position: fixed` 자손의 containing block이 되어 버리고 `position: sticky` 자손도 깨진다 -- 세션 화면의 `#report-wait`(fixed), `#mic-dock`(sticky)가 그 예). 6px 이동은 넣지 않는다. 토스트(`.toast`)는 fixed/sticky 자손이 없으므로 자기 것은 계속 이동해도 된다. 나가는 화면은 즉시 숨긴다(겹쳐 보이지 않게). `prefers-reduced-motion: reduce`면 효과 없음.
- **R2 다시 불러오기:** 이미 그려진 내용은 숨기지 않는다. 새 데이터가 오면 제자리에서 바꾼다. 기다리는 동안 `.is-refreshing`(투명도 0.55, 150ms)으로 흐리게. 실패하면 그때 숨긴다.
- **R3 처음 불러오기:** 실제 내용과 같은 크기의 스켈레톤(`.skeleton` 회색 블록, 부드러운 명암 반복)을 둔다. 스켈레톤 자리에도 사용자 규칙대로 문구를 둔다(`오늘의 추천 불러오는 중...` 등 -- 기존 문구 유지).
- **R4 알림:** `#notice`는 화면 위쪽 가운데에 떠 있는 토스트(`position: fixed`), 레이아웃에 영향 없음. 닫기 `×`. 들어오고 나갈 때 150ms 페이드. 기존 `notify(message)` 호출은 그대로(빈 문자열이면 닫힘).
- **R5 자리 유지:** 보였다 안 보였다 하는 상태 줄·보조 버튼은 `hidden`이 아니라 `.is-invisible`(visibility hidden + opacity 0, 150ms)로 숨겨 자리를 지킨다. 대상: `#start-status`, `#btn-cancel`, `#thinking`, `#library-progress`, `#today-alt`.
- **R6 고정 높이:** `#mic-hint`는 두 줄 높이 고정, 넘치면 앞부분을 말줄임(`-webkit-line-clamp: 2`). `#mic-dock` 전체 높이가 상태와 무관하게 같다.
- **R7 버튼 폭:** 글자가 바뀌는 버튼은 가장 긴 문구 기준 `min-width`(`.btn-stable`). 대상: 추천 카드 시작 버튼, `#btn-start`, 복습 `▶ 듣기`(마이페이지에서 사용), 세션 `#btn-end`(`리포트 만드는 중...`).
- **R8 펼치기·빠지기:** 교정 칩 펼침, 추천 카드 교체는 150ms 페이드(+ 칩 상세는 높이 전환 `grid-template-rows: 0fr → 1fr`). 목록에서 빠지는 카드는 150ms 페이드 후 제거.
- **R9 스크롤바:** `html { scrollbar-gutter: stable; }` -- 내용 길이에 따라 스크롤바가 생겼다 없어지며 폭이 변하지 않게.

## 범위

- 홈, 테마 화면, 세션, 리포트, 알림, 라우터, 공용 CSS.
- 마이페이지는 이 규칙으로 새로 만든다(마이페이지 계획 Task 3·4가 이 결과를 따른다).

## 확인

- 자동 테스트: 라우터 진입 표시, 토스트 동작, `loadHome` 다시 불러오기가 기존 카드를 숨기지 않음, 상태 줄이 `.is-invisible`로 자리를 지킴, 칩 펼침 클래스, CSS 규칙 존재(reduced-motion 포함).
- 브라우저 측정(`layout_probe`, 컨트롤러): 변경 전 기준(언어 전환 85px 이동)과 비교해 **다시 불러오기·상태 줄·알림에서 이동 0**, 세션 마이크 영역 높이 불변.
